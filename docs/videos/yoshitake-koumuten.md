# STUDIO 制作プロセス デモ — 株式会社吉武工務店

> 一覧ページ（`/`）と再生ページ（`/watch/yoshitake-koumuten`）から、シークバー付きのプレーヤーで見られます（`npm run dev` で起動）。詳しくは `../../README.md`。
> 動画のページ本体は `public/videos/yoshitake-koumuten/`（`index.html` はブラウザで直接開いても再生できます）。
> 画面は Windows 11（タスクバー・ポインター・IME・通知）で、長さは 5 分 31 秒 です。

画面録画用のデモページです。STUDIO のエディタを模した画面上でマウスカーソルが自動で動き、
「株式会社吉武工務店」サイト（https://yoshitake-koumuten.studio.site/）を空のページから組み立て、
レスポンシブ確認 → 公開 → 公開サイトの閲覧までを順番に再生します。

## 録画の手順

1. `public/videos/yoshitake-koumuten/index.html` を **Google Chrome** で開く（ダブルクリックで可。サーバーは不要。`npm run dev` 中なら http://localhost:3000/videos/yoshitake-koumuten/index.html でも可）
   - フォントと Google マップの読み込みにインターネット接続が必要です
   - 開いた直後の数秒で、再生中に使う文字のフォントをすべて先読みします（途中でフォントが切り替わるのを防ぐため）
2. **F11** で全画面表示にする（推奨：1920×1080、ブラウザのズーム 100%）
   - 録画前にページをクリックしても構いません（ボタンにフォーカス枠が残ることはありません）
3. 画面録画を開始する
4. **Space** キーで再生開始（右下のキー操作ヒントは再生開始と同時に消えます）
5. 公開サイトがトップに戻って止まったら録画を停止

再生時間は標準速度で 5 分 31 秒です（字幕・入力・ミスの場面を含む）。短くしたい場合は下の `speed` を使ってください。

## 再生される内容

| STEP | 内容 | ミスと修正 |
| --- | --- | --- |
| 1 | ヘッダー（背景色・会社名・ナビ） | **入力ミス**：「沿革」が「遠隔」と誤変換されたまま確定 → 消して入力し直し、変換候補から「沿革」を選ぶ |
| 2 | メインビジュアル | **操作ミス**：画像をヘッダーの中に入れてレイアウトが崩れる → レイヤーで確認 → Ctrl+Z で取り消して置き直す |
| 3 | ご挨拶セクション | |
| 4 | 写真・事業内容（ブロックの複製と書き換え） | |
| 5 | 会社情報・地図・沿革 | **エラー**：地図の「共有リンク」を貼って埋め込みに失敗 → クリップボード履歴（Win+V）から iframe コードを貼り直す |
| 6 | CMS と連携した「お知らせ」 | |
| 7 | お問い合わせフォーム・フッター | |
| 8 | タブレット / モバイル表示の確認 | **表示崩れ**：モバイルでフォームが画面からはみ出す → 「最大幅」を 100% に設定 |
| 9 | 公開 → 公開サイトの閲覧 | |

ミスが起きると字幕が赤い「⚠」表示になり、該当箇所に赤い枠が出ます。修正すると緑の「✓ 修正」に変わります。

### 日本語入力の再現

文字入力は、実際の Windows（Microsoft IME）での操作と同じ流れで再生されます。

- ローマ字を 1 キーずつ入力 → かなに変わっていく入力中の文字（点線の下線）
- 入力中は予測候補（ヒント）のウィンドウが表示され、1 キーごとに、それまでの読みに合う候補だけに絞り込まれます
  （合う候補がなくなると閉じます）。Tab で予測候補を選ぶ場面もあります
- Space で変換（文節ごとの下線、太い下線が変換中の文節）、2 回目の Space で変換候補の一覧 → Enter で確定
- レイヤー名と右パネルの名前は、確定した文字に合わせて変わります（新しいテキストは「テキスト」から始まります）
- 数字や記号は「半角/全角」キーで直接入力に切り替えて入力
- 画面下に、押しているキー（ローマ字・Space・Enter・半角/全角 など）と IME の状態（あ / A）を表示
- 一度直した変換は IME が覚えて、次からは正しく変換されます（STEP 5 の「沿革」）

## キー操作

| キー | 動作 |
| --- | --- |
| Space | 再生開始 / 一時停止 |
| ← / → | 5 秒戻る / 進む |
| R | 最初からやり直す |
| C | 字幕（STEP 表示）の表示 / 非表示 |
| H | キー操作ヒントの表示 / 非表示 |

## URL パラメータ

`index.html?speed=1.3&captions=0` のように指定します。

| パラメータ | 内容 |
| --- | --- |
| `speed=1.3` | 再生速度（1 が標準。1.3 で約 4 分 30 秒、1.5 で約 4 分 5 秒。ミスを直した後の緑の字幕は、読める長さのまま表示されます） |
| `from=5` | 指定したシーンから再生。ページを開くと、それより前のシーンを「準備中…」の表示の裏で進めて組み立て、そのシーンの開始状態で止まります（数秒）。「準備中…」が消えてから録画を開始し、Space で再生 |
| `t=83.5` | 指定した時刻（秒）まで画面の裏で進めて、その場面で止まります（`play=1` を付けるとそのまま再生） |
| `embed=1` | 再生ページの中で使う表示（キー操作ヒントなどを出さない）。再生ページから開いたときは自動で付きます |
| `to=5` | 指定したシーンを再生し終えたところで止める |
| `captions=0` | 字幕なしで再生（ミスの赤枠・緑枠は表示されます） |
| `autoplay=1` | 準備ができてから約 1.5 秒後に自動で再生開始 |

シーン番号：
0 イントロ / 1 ヘッダー / 2 メインビジュアル / 3 ご挨拶 / 4 写真・事業内容 / 5 会社情報・沿革 /
6 CMS（お知らせ）/ 7 お問い合わせフォーム・フッター / 8 レスポンシブ確認 / 9 公開 / 10 公開サイトの閲覧

シーンごとに分けて撮りたい場合は `from` と `to` を使ってください（例：`index.html?from=8&to=8` でレスポンシブ確認だけ）。
Space を押したままにしても一時停止が繰り返し切り替わることはありません。早送り中の Space は、準備ができしだい再生を開始します。

## 本番サイトとの同一性について

- キャンバスに組み上がるページは、公開中のサイトをブラウザで描画した結果の DOM
  （STUDIO が出力した HTML 構造・クラス・`data-s-*` 属性）と、STUDIO が生成した CSS をそのまま使っています。
- 入力の途中経過やミスの場面は一時的な表示で、最後に組み上がったページの DOM は本番サイトのものと 1 文字単位で一致します
  （全シーン実行後のキャンバスを元のスナップショットと比較して確認済み）。PC / モバイルの描画も本番と比較済みです。
- 画像はサイトで使われている画像ファイルを `assets/img/` に保存して参照しています。
  スナップショットは幅 1280px で取得しているため、その幅で STUDIO が配信したサイズの画像です
  （幅 1920px の公開サイト画面では、本番ならメインビジュアルなど 2 枚に一回り大きい画像が配信されるため、
  その 2 枚はごくわずかに粗く見えることがあります）。
- フォントは本番と同じ配信元（Google Fonts と STUDIO のフォント配信）から読み込みます。
- 右パネルの数値（サイズ・余白・フォント・行間・カラー名など）は、STUDIO が出力した CSS ルールから読み取った実際の設定値です。
  タブレット / モバイル表示中は、そのブレイクポイントの値を表示します（専用の値にはオレンジの点が付きます）。
- タブレット（768px）・モバイル（375px）表示には、STUDIO のブレイクポイント用 CSS（〜960px / 〜540px）がそのまま適用されます
  （ヘッダー右上のメニューボタン ≡ も本番と同じく表示されます）。
- 公開後の「サイトを開く」以降の画面も同じスナップショットを表示しています（STUDIO のスクロール表示アニメーションも再現）。
  カーソルを合わせたリンクや送信ボタンには、本番サイトと同じホバー表示（下線・色の変化）が出ます。
- CMS パネルの記事一覧（タイトル・日付・サムネイル・件数）は、スナップショットのお知らせ一覧から作っています。

## 画面の環境

- Windows 11 のデスクトップで、STUDIO のエディタは最大化した Chrome のタブ（`app.studio.design`、プロジェクト ID はぼかし）で開いています。
  公開後の「サイトを開く」は同じウィンドウの新しいタブ（`yoshitake-koumuten.studio.site`、サイトのファビコン）になります
- タスクバーの時計は 2026/03/10 10:42 から、動画の経過時間に合わせて進みます（お知らせの最新 2026.2.21 と矛盾しない日付）
- 地図の「共有リンク」は実在しない短縮 URL の例です（埋め込みに失敗する場面のため）。iframe コードは本番の地図の埋め込みコードです
- マウスポインターは Windows 標準のポインター画像、クリップボード履歴（Win + V）は Windows 11 の見た目です

## 演出であるもの

- エディタの画面（ツールバー、左右のパネル、公開ダイアログなど）は、STUDIO での作業の流れを伝えるための簡易的な再現です。
  実際の STUDIO の画面と細部まで同一ではありません（エディタはログインが必要なため取り込めません）。エディタ左上のロゴ（/S）とタブのファビコンは本物の STUDIO のもの（app.studio.design）です
  （公開サイト画面左下の「Created in STUDIO」バッジは、本番サイトに実際に表示されているものです）。
- 要素が空の状態から追加され、文字が入力され、画像が差し込まれる順序や速さ、4 つのミスとその修正は演出です。
  埋め込みエラーのメッセージ文言やクリップボード履歴の画面も、流れを伝えるための再現です。

## サイトを更新した場合

STUDIO 側で内容を変更したら、スナップショットを取り直すとデモにも反映されます（Node.js と Chrome が必要）。

```
npm install                              （初回のみ。movie/ フォルダで実行）
npm run snapshot:yoshitake-koumuten
```

`js/site-snapshot.js` と `assets/img/` が更新されます。

自動で反映されるもの：

- キャンバスに組み上がるページと公開サイト画面（DOM・CSS・画像）
- 右パネルのサイズ・余白・フォント・カラーなどの値（CSS から読み取るため）
- CMS パネルの記事一覧と、CMS リストに並ぶ記事のレイヤー名
- 文章を変えた場合：その文章の入力手順（`js/scenario.js` の `JA`）は新しい文章と一致しなくなりますが、
  その文章だけ自動で通常の入力表示に切り替わるため、ページの内容は常に本番と同じになります
  （ローマ字入力・変換の表示も合わせたい場合は `JA` のローマ字・変換候補・読みを書き換えてください）

手作業での修正が必要なもの：

- 画像を差し替えた・増やした場合：`js/editor.js` の `ASSETS`（アセットパネルの画像ファイル名）と、
  `js/scenario.js` でドラッグする画像の ID（`'f1b0faa1'` など）
- プロジェクトのカラー・フォントを変えた場合：`js/editor.js` の `COLORS` / `FONT_VARS` / `FONT_LIST`
- ページのタイトル・説明文・OGP 画像：`js/editor.js` の `pageHtml()` と `assets/img/ogp.jpg`
- ファビコン：`assets/img/favicon.png`（ツールではダウンロードされません）
- ページ一覧（左パネル「ページ」）とプロジェクト名：`index.html`
- ナビの「会社情報・沿革」の文言を変えた場合：入力ミス（STEP 1）の台本 `js/scenario.js` の `JA.nav[2]` を新しい文言に合わせて書き換え
  （一致しないとその文字は通常の入力表示になり、入力ミスの場面は再生されません）
- フォームや CMS リストの設定を変えた場合：右パネルの固定表示（フォームの「項目数」「送信後」、CMS の「表示件数」「並び順」「リンク先」）は
  `js/editor.js` の `Props.elHtml()` を書き換え
- セクションの構成を大きく変えた場合：`js/scenario.js` の `resolve()`（要素の対応付け）と各シーン
