# 制作プロセス デモ — Soup Stock Tokyo 公式オンラインショップ（ec.soup-stock-tokyo.com）在庫連携

> 一覧ページ（`/`）と再生ページ（`/watch/soup-stock-tokyo`）から、シークバー付きのプレーヤーで見られます（`npm run dev` で起動）。詳しくは `../../README.md`。
> 動画のページ本体は `public/videos/soup-stock-tokyo/`（`index.html` はブラウザで直接開いても再生できます）。
> 画面は Windows 11（タスクバー・ポインター・IME）で、長さは 5 分 41 秒です。

画面録画用のデモページです。Windows 11 のデスクトップを模した画面上でマウスカーソルが自動で動き、
Soup Stock Tokyo 公式オンラインショップ（https://ec.soup-stock-tokyo.com/）の **倉庫・店舗の在庫を Shopify に同期する仕組みを作る工程** を順番に再生します。

**在庫連携の設計 → ロケーション設定 → 同期スクリプト → エラー処理・再試行 → 定期実行 → 在庫・ストア表示の確認**

## 最初に確認していただきたいこと

- ec.soup-stock-tokyo.com は **Shopify（テーマは Prestige 5.5 をカスタマイズしたもの）で運営されている実在のストア** です。
  このデモは「冷凍・常温倉庫と店舗の在庫を EC と連携する」としたらどう作るか、という **工程の再現** で、実際の開発作業の記録ではありません。
- **ストアの実データ**：商品名・スープ / カレーの名前・SKU（`106001A`・`004355S`・`004346C` など）・商品タイプとタグ（冷凍 / 常温）、
  選べるセットの中身のスープのうち商品名に【完売】と付いているもの、ブラウザに表示されるストアの画面（トップ・冷凍スープの一覧・商品ページ・選べるセットのページ、PC / スマートフォン）は、公開中のストアから取得したものです。
- **再現用に作ったもの**：倉庫管理システム（WMS）とその在庫 CSV（品番の持ち方・倉庫コード・引当可能数・出荷待ち）、在庫の数字、ロケーションの名前と住所、
  「在庫 9,999 のまま運用している」という前提、API のトークン・ID・レスポンス、GitHub のリポジトリ（`soupstocktokyo/sst-inventory-sync`）・アカウント（`sst-ec-dev`）と Actions の実行結果（どちらも GitHub 上には存在しません）。住所はぼかしています。
- **GitHub Actions の画面は本物の GitHub の画面** です（2026-11-17 取り込み。下の「GitHub Actions の画面について」）。
- 「人気の8スープセット/ギフトボックス」が倉庫で在庫切れになり「売り切れ」と表示される場面は演出です（公開中のストアの状態ではありません）。
- Soup Stock Tokyo（株式会社スープストックトーキョー）は実在の企業です。このデモはローカルのファイルとしてだけ使ってください（Web に公開しないでください）。

## 録画の手順

1. `public/videos/soup-stock-tokyo/index.html` を **Google Chrome** で開く（ダブルクリックで可。サーバーは不要。`npm run dev` 中なら http://localhost:3000/videos/soup-stock-tokyo/index.html でも可）
   - 準備に 5〜20 秒ほどかかります（ストアの画面・画像・フォントの先読み）。タイトル画面が出たら準備完了です
2. **F11** で全画面表示にする（推奨：1920×1080、ブラウザのズーム 100%）
3. 画面録画を開始する
4. **Space** キーで再生開始
5. 最後に「倉庫・店舗と EC の在庫連携が完了」と出たら録画を停止

## 再生される内容

| STEP | 画面 | 内容 | ミスと修正 |
| --- | --- | --- | --- |
| 1 在庫連携の設計 | Chrome（Shopify 管理画面）・VS Code | 選べるセットの中身のスープ（商品「（単品）」のバリエーション）は在庫 9,999 のまま、完売は商品名に【完売】と手で書く運用 → 設計書 `docs/inventory-sync.md`（在庫の正は WMS の引当可能数、ロケーション、15 分ごとの同期） | |
| 2 ロケーション設定 | Chrome（設定 > ロケーション）・VS Code | 常温倉庫（D01）を追加してオンライン注文の発送を有効に、店舗（POS）はオンライン注文を発送しない設定に、ロケーション ID（URL の末尾）を `src/locations.mjs` にコピー、注文ルーティングの優先順位を確認 | （ここで店舗のページの ID を貼ってしまう → STEP 6 で発覚） |
| 3 同期スクリプト | VS Code ＋ ターミナル | WMS の在庫 CSV を確認、`src/sync-inventory.mjs` に照合（品番＋区分 → SKU → 在庫アイテム ID）と `inventorySetQuantities` の入力を書き、`--dry-run` で照合 | **照合エラー**：SKU が 115 件見つからない（WMS の品番は数値で先頭の 0 がない：`4095S` ⇔ `004095S`）→ `padStart(6, '0')` でゼロ埋めして全件照合 |
| 4 エラー処理・再試行 | VS Code ＋ ターミナル | 本番ストアに同期 | **API エラー**：1 件ずつのミューテーションを全件並列に送って `THROTTLED`（コストの上限）→ 100 件ずつまとめて送り、`withRetry` で回復を待って再試行 → 全件更新 |
| 5 定期実行 | VS Code・Chrome（設定 > 通知 > Webhook・GitHub Actions） | ワークフローに 15 分ごとのスケジュール（cron）を追加して push、注文作成の Webhook を WMS に向けて作成（同期の合間の売り越し防止）、定期実行のログを確認 | |
| 6 在庫・ストア表示の確認 | Chrome（管理画面・ストア）・VS Code | 商品一覧と「（単品）」の在庫が実数に（【完売】のスープは 0）、在庫ページ（冷凍倉庫）が WMS と一致、倉庫で在庫切れのセットが一覧・商品ページで自動的に「売り切れ」→ 入荷後の次の定期実行で「カートに追加する」に戻る | **ロケーション違い**：常温倉庫の販売可能数がすべて 0、常温の在庫が店舗（POS）に入っていた（D01 に店舗のロケーション ID を貼っていた）→ 常温倉庫の ID に直して再同期 |
| 公開ストアの確認 | Chrome | 選べる「スープとカレー」セットのページ、トップページ | |

### 日本語入力（Microsoft IME と同じ流れ）

スクリプトの列名（`r['品番']` `r['引当可能数']` など）・コメント・コミットメッセージの日本語は、ローマ字を 1 キーずつ入力 → 変換 → 確定 の流れで入力しています。
英数字は IME をオフ（半角/全角）にして入力し、画面下に押したキーを表示します。

ほかのデモと同じです（`../../README.md`）。**Space** 再生 / 一時停止、**R** 最初から、**C** 字幕、**H** ヒント、`?t=秒` `?from=シーン番号` `?speed=1.3` `?captions=0`。

## 本番サイトとの同一性について

- ブラウザに表示されるストア（トップページ・冷凍スープの一覧・人気の8スープセット・選べる「スープとカレー」10個セット、PC 幅 1920px / スマートフォン幅 390px）は、
  公開中のストアをブラウザで開き、ストアのスクリプトが動いた後の画面を **そのまま取り込んだもの** です（`js/site-snapshot.js`・`assets/site/`）。
  スタイルシートは本番のファイルのまま、画像はその幅で表示されていたサイズのものです。スクリプト（計測タグ・アプリ）は取り込んでいません。
- 商品ページの右の列（価格・カートボタン）は本番ではスクロールに追従しますが、カートボタンまでスクロールして見せるため追従を外しています（`js/config.js` の `snapshot.css`）。
- 「売り切れ」の状態は、取り込んだ画面の商品カードにラベルを足し、商品ページのボタンを差し替えることで再現しています（`js/scenario.js` の `giftSoldOut` / `giftSoldOutBtn`）。
- 管理画面のスープ・カレー・セットの名前・SKU・画像は、ストアの公開商品データ（`/products.json`）と選べるセットのページから取得したものです。

## GitHub Actions の画面について

STEP 5 の定期実行のジョブ画面（実行中 → 完了）と STEP 6 の 2 回目の実行の概要画面は、**github.com の実際のページ** を取り込んだものです（`js/github-snapshot.js`・`assets/github/`）。

- 取り込み元：公開リポジトリの Actions のページを、ログインせずに開いたもの（終了したスケジュール実行の概要とジョブ、実行中のジョブ。ジョブが 1 つの実行）。GitHub が送る HTML・あとから取得するデータ・スタイルシート（ライトテーマ）は GitHub のものそのままで、スクリプトは取り込んでいません
- 名前の置き換え：取り込み元のリポジトリ・ワークフロー・ジョブ・人・コミットの名前は、描画の前にすべてこの動画のもの（`soupstocktokyo/sst-inventory-sync`・`inventory-sync`・`sync`・`sst-ec-dev`・`b7e41c9`）に置き換えています。取り込み元の名前が残っていないことはツールが確認します
- **ログインした状態のヘッダー**（メニュー・ロゴ・リポジトリ名・検索・作成・Issues・Pull requests・受信トレイ・アバター）は、GitHub 自身のスクリプトが描いたものです（ナビゲーションの部品に「ログイン中のユーザー」を渡して描画）。リポジトリのタブは管理者が見る非公開リポジトリのもの（Projects・Settings あり、Discussions なし）
- アバターは、GitHub が写真のないアカウントに付けるアイデンティコン（GitHub の方式で `sst-ec-dev` から生成）です
- ジョブのステップ（`.github/workflows/inventory-sync.yml` の 8 つ）は、取り込んだページのステップ要素から作っています。実行中・完了・待機のアイコン、実行中のタイトルのアイコン、サイドバーのジョブのアイコンも GitHub のページのものです
- **再現した部分**：右上のボタン（ログインした所有者が見る「Cancel workflow」「Re-run all jobs」と「…」。ログインしていない画面には「Sign in to view logs」しかないため、GitHub のボタンのクラス `btn` で置いています）、ログの行（GitHub のログ表示の行のマークアップ `CheckStep-line` で、ワークフローが出力する内容を入れています。ログはログインしないと見られないため）、時刻・所要時間・実行番号

## 演出であるもの

- **画面の環境**：VS Code は今の既定の見た目です（Dark Modern テーマ、VS Code 自身のアイコン codicon、Seti のファイルアイコン、ミニマップ。`public/shared/vscode.css` / `vscode.js`）。
  Shopify の管理画面は左上のロゴとタブのファビコンが本物です（`npm run favicons`）。ファビコンのないページ（開発サーバーなど）のタブには Chrome 本体のアイコンを表示しています。

- Shopify の管理画面は **見た目を似せた再現** です。
- ターミナルの出力（npm スクリプト・git・エラーの表示）は、実際のコマンドの出力の形式に合わせて表示しています。API のコストの数字は説明のためのものです。
- プロジェクトのファイル（`src/` など）は説明のための最小限のもので、ストアの実際のシステムのソースではありません。
- **時刻**：画面の時計は 2026/11/07 15:41 から進み、定期実行（15 分ごと）の「15:45 の実行」を 15:45 にそのまま見ます。
  入荷のあとは録画のカットで 16:01 に進み（タスクバーの時計も 16:01 に変わります。`Win11.skipTo('16:01')`）、「16:00 の実行」の結果を確認します。
  WMS の在庫 CSV の更新日時は直前の 15:30 です。

## サイトを更新した場合

```
npm run snapshot -- soup-stock-tokyo      ストアの画面・画像・商品データを取り込み直す（tools/snapshot-store.js → 画像は WebP に変換）
node tools/snapshots/soup-stock-tokyo/capture-github.js && node tools/webp.js soup-stock-tokyo
                                         GitHub Actions の画面を取り込み直す（その時点で実行中のジョブがある公開リポジトリから）
npm run timeline -- soup-stock-tokyo     長さ・チャプターの測定とサムネイルの撮影
```

取り込む内容（ページ・商品・取り除く要素）は `js/config.js` の `snapshot` で設定します。

## ファイル構成

```
index.html            ページ本体（共通の部品は public/shared/kit/ と public/shared/）
css/video.css         このデモだけの見た目（ロケーション・在庫、GitHub の画面の枠）
js/config.js          デモの設定（工程・タイトル画面・ストア・取り込むページ）
js/site-snapshot.js   取り込んだストアの画面と商品データ（自動生成）
js/github-snapshot.js 取り込んだ GitHub Actions の画面（自動生成：tools/snapshots/soup-stock-tokyo/capture-github.js）
js/files.js           VS Code に表示するプロジェクトのファイル（同期スクリプト・WMS の CSV・ワークフロー）
js/apps.js            Shopify 管理画面の各ページ（（単品）・ロケーション・在庫）と、GitHub Actions の画面の状態（実行中 / 完了・ログ）
js/scenario.js        台本（シーンごとの操作・字幕・ミスと修正）
assets/site/          取り込んだ画像・フォント（自動生成）
assets/github/        GitHub の画面の画像・アバター（自動生成）
```
