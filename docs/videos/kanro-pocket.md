# 制作プロセス デモ — Kanro POCKeT（kanro.jp）Shopify と業務システムの連携

> 一覧ページ（`/`）と再生ページ（`/watch/kanro-pocket`）から、シークバー付きのプレーヤーで見られます（`npm run dev` で起動）。詳しくは `../../README.md`。
> 動画のページ本体は `public/videos/kanro-pocket/`（`index.html` はブラウザで直接開いても再生できます）。
> 画面は Windows 11（タスクバー・ポインター・IME）で、長さは 6 分 46 秒です。

画面録画用のデモページです。Windows 11 のデスクトップを模した画面上でマウスカーソルが自動で動き、
カンロ株式会社のオンラインショップ Kanro POCKeT（https://kanro.jp/）を **社内の業務システム（基幹・物流 WMS・会員基盤）とつなぐ工程** を順番に再生します。

**連携の全体設計 → 受注連携（Webhook）→ 在庫取り込み → 出荷連携 → 会員連携 → 監視・リトライ**

## 最初に確認していただきたいこと

- kanro.jp は **Shopify（テーマは Impulse 3.6 をカスタマイズしたもの・GitHub 連携）で運営されている実在のストア** です。
  このデモは「Shopify のストアと社内システムを中継サーバーでつなぐ」としたらどう進めるか、という **連携工程の再現** で、実際の開発作業の記録ではありません。
  Kanro POCKeT が実際にどのシステムとどのように連携しているかは公開されておらず、このデモの構成（ec-gateway・SFTP・CSV の形式など）は再現用に作ったものです。
- **ストアの実データ**：商品名・価格・SKU（5 桁の商品コード：00173 など）・商品画像、ラベル用のタグ（`_label_オンライン限定` など）、
  ブラウザに表示されるストアの画面（トップページ・商品ページ・アレルギー表示）は、公開中のストアから取得したものです。
- **再現用に作ったもの**：中継サーバー（ec-gateway）のコードとモニター画面、基幹・WMS・会員基盤とその CSV / API、在庫数、注文（#1001〜#1004）、
  お客様・会員データ（ランク・ポイント）、送り状番号、アプリの認証情報、ロケーション名、ドメイン（`ec-gateway.kanro-pocket.example`）。
  お客様の氏名・連絡先・住所と認証情報はぼかしています。
- カンロ株式会社は実在の企業です。このデモはローカルのファイルとしてだけ使ってください（Web に公開しないでください）。

## 録画の手順

1. `public/videos/kanro-pocket/index.html` を **Google Chrome** で開く（ダブルクリックで可。サーバーは不要。`npm run dev` 中なら http://localhost:3000/videos/kanro-pocket/index.html でも可）
   - 準備に 5〜20 秒ほどかかります（ストアの画面・画像・フォントの先読み）。タイトル画面が出たら準備完了です
2. **F11** で全画面表示にする（推奨：1920×1080、ブラウザのズーム 100%）
3. 画面録画を開始する
4. **Space** キーで再生開始
5. 最後に「受注・在庫・出荷・会員の連携が完了」と出たら録画を停止

## 再生される内容

| STEP | 画面 | 内容 | ミスと修正 |
| --- | --- | --- | --- |
| 1 連携の全体設計 | VS Code・Chrome（Shopify 管理画面） | 連携設計（受注・在庫・出荷・会員の 4 つの流れ）、`shopify.app.toml` に Webhook（orders/paid）を登録、アプリの API 認証情報を `.env` に保存 | |
| 2 受注連携 | VS Code ＋ ターミナル・Chrome（連携モニター） | 注文 → 基幹の受注 CSV（1 明細 1 行・日本時間）の変換、Webhook の署名（HMAC）の検証、`shopify app deploy`、`shopify app webhook trigger` でテスト | **署名エラー**：解析済みの本文を `JSON.stringify` し直して検証していたため 401（HMAC mismatch）→ `express.raw()` で届いた本文のまま検証して 200 |
| 3 在庫取り込み | Chrome（在庫・ロケーション）・VS Code | WMS の在庫 CSV（15 分ごと）から、変わった SKU だけを `inventorySetQuantities` で 250 件ずつ設定 → 在庫画面で確認 | |
| 4 出荷連携 | VS Code・Chrome（注文管理） | WMS の出荷実績 → `fulfillmentCreate`（送り状番号・ヤマト運輸の追跡 URL）で「発送済み」に | **通知漏れ**：テスト中に入れた `notifyCustomer: false` のまま → 発送完了メールが送られていない → `true` に直してデプロイ、発送済みの注文には管理画面から通知を送信 |
| 5 会員連携 | Chrome（設定 > カスタムデータ・顧客）・VS Code | 顧客メタフィールド「保有ポイント」（整数）の定義を追加、会員基盤の差分を `metafieldsSet` で同期、マイページのスニペット、顧客の詳細で確認 | |
| 6 監視・リトライ | Chrome（連携モニター）・VS Code | Webhook・ジョブ・基幹連携・デッドレターの確認 | **二重取り込み**：基幹への送信（6.4 秒）を待ってから応答したため Shopify が Webhook を再送 → 同じ注文が 2 回送られて基幹で重複エラー → 同じ `X-Shopify-Event-Id` は 1 回だけ処理し、200 を先に返す。重複分はデッドレターから破棄 |
| 公開ストアの確認 | Chrome | kanro.jp のトップページ（新商品・ヒトツブカンロ・オンライン限定のラベル）と商品ページ（カート・アレルギー表示） | |

### 日本語入力（Microsoft IME と同じ流れ）

コードのコメント・列名（`r['送り状番号']` など）・メタフィールドの名前は、ローマ字を 1 キーずつ入力 → 変換 → 確定 の流れで入力しています。
英数字は IME をオフ（半角/全角）にして入力し、画面下に押したキーを表示します。

## キー操作 / URL パラメータ

ほかのデモと同じです（`../../README.md`）。**Space** 再生 / 一時停止、**R** 最初から、**C** 字幕、**H** ヒント、`?t=秒` `?from=シーン番号` `?speed=1.3` `?captions=0`。

## 本番サイトとの同一性について

- ブラウザに表示されるストア（kanro.jp のトップページと商品ページ「ピュレグミプレミアム山梨産白桃」、PC 幅 1920px / スマートフォン幅 390px）は、
  公開中のストアをブラウザで開き、ストアのスクリプトが動いた後の画面を **そのまま取り込んだもの** です（`js/site-snapshot.js`・`assets/site/`）。
  スタイルシートは本番のファイルのまま、画像はその幅で表示されていたサイズのものです。スクリプト（計測タグ・アプリ）は取り込んでいません。
- 管理画面の在庫・注文に出る商品名・価格・SKU・画像は、ストアの公開商品データ（`/products.json`）から取得したものです。

## 演出であるもの

- **画面の環境**：VS Code は今の既定の見た目です（Dark Modern テーマ、VS Code 自身のアイコン codicon、Seti のファイルアイコン、ミニマップ。`public/shared/vscode.css` / `vscode.js`）。
  Shopify の管理画面は左上のロゴとタブのファビコンが本物です（`npm run favicons`）。ファビコンのないページ（開発サーバーなど）のタブには Chrome 本体のアイコンを表示しています。

- Shopify の管理画面と連携モニターは **見た目を似せた再現** です（管理画面はログインが必要なため取り込めません。左上のロゴとタブのファビコンは本物の Shopify のもの、連携モニターは自作の画面のためファビコンなし＝Chrome 本体のアイコン）。件数・処理時間・時刻の表示は演出です。
- ターミナルの出力（`shopify app deploy` / `webhook trigger`、ジョブの結果）は、実際のコマンドの出力の形式に合わせて表示しています。
- 「発送通知を送信」は、発送済みにした後でお客様に発送のお知らせを送り直す操作を、分かりやすい 1 つのボタンにまとめたものです。

## サイトを更新した場合

```
npm run snapshot -- kanro-pocket      ストアの画面・画像・商品データを取り込み直す（tools/snapshot-store.js → 画像は WebP に変換）
npm run timeline -- kanro-pocket     長さ・チャプターの測定とサムネイルの撮影
```

取り込む内容（ページ・商品・取り除く要素）は `js/config.js` の `snapshot` で設定します。
