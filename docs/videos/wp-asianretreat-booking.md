# 制作プロセス デモ — アジアンリトリート（asianretreat.jp）WordPress 予約システムの導入

> 一覧ページ（`/`）と再生ページ（`/watch/wp-asianretreat-booking`）から、シークバー付きのプレーヤーで見られます（`npm run dev` で起動）。詳しくは `../../README.md`。
> 動画のページ本体は `public/videos/wp-asianretreat-booking/`（`index.html` はブラウザで直接開いても再生できます）。
> 画面は Windows 11（タスクバー・ポインター・IME）で、長さは 5 分 21 秒です。

画面録画用のデモページです。Windows 11 のデスクトップを模した画面上でマウスカーソルが自動で動き、湘南発の出張マッサージ
「アジアンリトリート」（https://asianretreat.jp/）の WordPress に **予約システム（カレンダー予約・オンライン決済・通知メール・予約管理）を導入する工程** を順番に再生します。

**プラグインの導入 → メニューと料金 → 営業時間・予約枠 → 入力項目・通知メール → オンライン決済 → 予約ページ・テスト予約 → 予約の管理 → 公開中のサイト**

## 最初に確認していただきたいこと

- asianretreat.jp は **WordPress で運営されている実在の事業者のサイト** です（テーマは TCD の有料テーマ「HAKU」`haku_tcd080`、Site Kit by Google）。
  公開中の予約ページ（`/booking/`）は LINE とメール（Google フォーム）の案内だけで、予約プラグインは入っていません。このデモは
  「このサイトに WEB 予約を入れる」としたらどう進めるか、という **工程の再現** で、実際の作業の記録ではありません。**ローカルでの利用に限ってください。**
- **本物のもの**
  - WordPress の管理画面は **すべて本物の WordPress 7.1.4 の画面** です（日本語）。予約プラグイン **Booking Package 1.7.48**（wordpress.org・日本の開発者・
    公式の日本語翻訳）は「プラグインを追加」から実際に検索・インストール・有効化し、動画に出る設定はすべてプラグイン自身の画面で実際に行っています：
    カレンダーの名前、サービス 10 件（1 件目はフォームに入力・保存）、「この機能を有効化する」の切り替え、11/19 の時間枠（「時間枠を設定」で 10:00〜20:00・30 分間隔 → 適用 → 保存）、
    入力フィールドの日本語化（「ご訪問先のご住所」は必須に）、通知メール（新規・顧客向け / 管理者向け）、一般設定のサイト名・メールアドレス（お店の名前と、公開ページに載っているアドレス）。
  - **予約ページ（`/booking/`）の画面も本物の WordPress のフロント** です。テーマは有料でインストールできないため、同じフォルダー名・名前・バージョンの
    代わりのテーマ（`haku_tcd080`）が **公開中の /booking/ のページそのものの HTML**（asianretreat.jp から取得、スクリプトは除去、スタイルシートは公開サイトのもの）を
    本文の前後に出力し、本文に Booking Package のショートコードを入れています。カレンダー・時間枠・メニュー・入力フォーム・完了画面は、
    そのページの中でプラグインが実際に描いたもので、**テスト予約も実際にその画面から行っています**（11/21 13:00）。
  - 3 つのミスのうち 2 つはプラグイン自身の動きです：サービスを登録しても機能が OFF のままだと、プラグインが赤字で
    「有効なアイテムがあるにも関わらず、「サービス」の機能が無効になっています。」と警告すること、準備時間なしでは 13:00〜14:30 の予約の直後の 14:30 が選べること（キャプチャーした本物の予約画面）。
  - Stripe・PayPal の決済が **Booking Package の有料購読（サブスクリプション）の機能** であること、無料版の一般設定に「有料購読への加入が必要」と
    出ること、「有料版の購読」タブの画面は本物です。
  - メニュー名・施術時間・料金（税込）は公開中の「メニュー＆料金」ページのもの、出張エリア（藤沢市・鎌倉市・茅ヶ崎市 ほか）と予約ページの文章は公開中の
    「ご予約」ページのもの、お店のメールアドレス（asianretreat.jp@gmail.com）は公開ページに載っているものです。サイトのトップは公開中の画面の取り込みです（`js/site-snapshot.js`）。
- **再現したもの（本物ではないもの）**
  - **有料版（有料購読）の状態**：動画では 5 章「オンライン決済」で有料版を購読し、それ以降の Booking Package の画面は有料版の見た目にしています（`js/apps.js` の `AR.unlock`：
    赤字の「有料購読への加入が必要」を消し、その行の入力欄を使える状態に）。無料版で無効になっている機能のうち、動画で使うのは次の 3 つで、いずれも有料版の機能です
    （プラグインのコードで確認：`Setting.php` の `isExtensionsValid => 1`、`Schedule.php` の `applyFreePlanLimits` は無料版で準備時間を 0 にします）：
    - 一般設定の **Stripe**（有効・公開鍵・シークレットキー）— 再現は「購読後」の一般設定（Stripe 欄）
    - カレンダーの設定の **準備時間**（30 分・予約の前後）— 再現はカレンダーの設定（cal-prep / cal-prep-set）と、準備時間が効いた後の予約画面（12:00 と 14:30 を予約不可に：`AR.prepSlots`）
    - カレンダーの設定の支払い方法の **「Stripe で支払う」** — 再現はカレンダーの設定（cal-payment 以降）
    取り込みは無料版のまま行っています（キャプチャー中の準備時間は PHP で DB に書きましたが、無料版の予約画面には効きません）。
  - **オンライン決済まわり**：有料購読はしていません（できません）。「購読後」の一般設定の Stripe 欄（入力欄が使える状態・テスト用の鍵の入力）と、
    予約フォームのお支払い方法・Stripe のカード入力欄は、無料版の本物の画面に重ねた **再現** です（`js/apps.js` の `AR.paid` / `AR.card`）。
    鍵はでたらめの文字列で、入力中もぼかしています。カード番号は Stripe のテストカード（4242 4242 4242 4242）です。Stripe のダッシュボードは出しません（ログインが必要）。
  - カレンダーの「支払い方法」で「Stripe で支払う」にチェックを入れる場面は、無料版の本物の画面の本物のチェックボックスですが、実際のキャプチャーでは
    「現地で支払う」のままテスト予約をしています（無料版では Stripe の鍵を保存できないため）。
  - **受信トレイ**：Gmail はログインが必要なため、ロゴのない Web メールの見た目で再現しています（タブのファビコンだけ本物の gmail.ico）。メールの本文は、
    プラグインの通知テンプレート（動画で貼り付けた文面）のタグを予約の内容で埋めたものです。Playground はメールを送れないため（`pre_wp_mail` で送信を止めています）、
    実際に届いたメールではありません。
  - 作業の順番・ご依頼の内容（`docs/web-booking.md`）・受付時間（10:00〜20:00、セラピスト 1 名）・準備時間 30 分・3 つのミス。受付時間は公開サイトに
    載っていないため仮の値です。テスト予約のお名前・住所・電話番号・メールアドレスは架空です（example.jp）。
  - ターミナル（`ssh asianretreat` と `wp db export`）の出力、サーバーのパス。
  - カレンダーの設定タブのメールアドレス（受信用・送信用）と送信者名は、動画の中でお店のアドレス・名前に入力していますが、取り込んだ画面の入力欄を再生時に書き換えたものです（取り込みではプラグインの初期値のまま）。
  - 6 章で通知メールの設定を開き直す場面は、4 章で入力・貼り付けした同じ画面（入力欄はそのときの内容のまま）を見せています。取り込みでは本当に保存していますが、保存後に開き直した画面は取り込んでいません。
  - 時間枠は 11/19 の 1 日分を画面で作り、残りの日（11/20〜12/31）は同じ枠をプラグインの保存と同じ INSERT で入れています（動画では「まとめて公開」と説明）。
  - 他の 9 件のサービスも同じ画面・同じ手順で保存していますが、動画では 1 件目だけ入力を見せています。

## 録画の手順

1. `npm run dev` で一覧ページを開き、「特別」タブの「アジアンリトリート — WordPress 予約システムの導入」を再生します（または `public/videos/wp-asianretreat-booking/index.html` を直接開きます）。
2. ブラウザを全画面（F11）にして、画面録画を開始 → Space キーで再生。終わると最後の画面で止まります。

### 日本語入力（Microsoft IME と同じ流れ）

カレンダーの名前・サービス名・入力フィールド名・テスト予約のお名前（漢字・カタカナ）・住所は、ローマ字入力 → 変換 → 確定の流れで入力しています（`js/scenario.js` の `JA`）。

## キー操作 / URL パラメータ

Space＝再生 / 一時停止、R＝最初から、C＝字幕の表示切替、H＝ヒントを隠す。`?t=83`（秒）・`?from=4`（4 番目の場面から）・`?speed=1.3`・`?captions=0`。

## 本番サイトとの同一性について

- 予約ページは、公開中の `/booking/` の HTML（ヘッダー・ページ見出しの画像・本文・フッター）とスタイルシートをそのまま使い、本文の先頭にプラグインのカレンダーを入れたものです。
  テーマのスクリプトは使っていないため、スクロールで表示される要素は表示された後の状態（`dc2_animate_item active`）にしています。`<html>` の `pc` / `mobile` は
  HAKU と同じく `wp_is_mobile()` で切り替えています（スマートフォンの画面は iPhone のユーザーエージェント・幅 390px で取り込み）。
- 公開中のサイトには、まだ予約カレンダーはありません（2026-11 時点で LINE・メールでの受付）。

## WordPress の画面について

- `node tools/snapshots/wp-asianretreat-booking/capture-wp.js [スクリーンショットのフォルダー]` → `node tools/webp.js wp-asianretreat-booking` で取り込み直せます（WordPress Playground・アカウント不要）。
- 変更している点（`tools/wp/playground.js` の共通ルール）：Playground のアドレス → `https://asianretreat.jp`、取り込んだ日 → 2026-11-12（動画の日付）、入力する欄 → 見た目を合わせた入力欄。
  この動画で追加した変更：管理画面のカレンダーで取り込んだ日より前の日に付く `closeDay`（グレー）を、動画の今日（12 日）より前の日だけに、プラグインの m/d/Y 形式の取り込み日（日付フォーマットの見本など）を 11/12/2026 に（`--fix-today`）、
  サービスの有効期限の日付の初期値（取り込んだ日）を 12 日に、テスト予約の住所の表記。
- プラグインの `alert()` / `confirm()` は、取り込み中に「OK」で閉じています。

## 演出であるもの

- 時刻（タスクバーの時計）は作業の区切りで進めています（`Win11.skipTo`）。サービス 10 件のうち 9 件、12 月末までの時間枠の公開は、保存したところを省略しています。
- 2 回目のテスト予約（11/22 11:00）のメールは、1 回目と同じテンプレートに住所のタグを足したもので、画面での予約操作は省略しています。

## サイトを更新した場合

- トップページ：`npm run snapshot -- wp-asianretreat-booking`（`js/config.js` の `snapshot`）。
- 予約ページと管理画面：上の `capture-wp.js` を実行（公開中の /booking/ を取り込み直します）。その後 `npm run verify -- wp-asianretreat-booking` と `npm run check -- wp-asianretreat-booking`。
