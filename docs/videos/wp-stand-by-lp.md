# 制作プロセス デモ — Stand by Beauty Clinic（stand-by.jp）キャンペーン LP の制作（WordPress）

> 一覧ページ（`/`）と再生ページ（`/watch/wp-stand-by-lp`）から、シークバー付きのプレーヤーで見られます（`npm run dev` で起動）。詳しくは `../../README.md`。
> 動画のページ本体は `public/videos/wp-stand-by-lp/`（`index.html` はブラウザで直接開いても再生できます）。
> 画面は Windows 11（タスクバー・ポインター・IME）で、長さは 6 分 17 秒です。

画面録画用のデモページです。Windows 11 のデスクトップを模した画面上でマウスカーソルが自動で動き、
明治神宮前の美容クリニック「Stand by Beauty Clinic」（https://stand-by.jp/）の **12-1月限定キャンペーンのランディングページ（LP）を WordPress で作る工程** を順番に再生します。

**構成・導線設計 → キャンペーン価格（料金表）→ LP の作成（固定ページ）→ トップからの導線 → 固定ボタン（CTA）→ スマホで確認**

## 最初に確認していただきたいこと

- stand-by.jp は **WordPress で運営されている実在のクリニックのサイト** です（WordPress は `/wp` に置かれ、サイトはドメイン直下）。
  このデモは、公開中の「12-1月限定キャンペーン」の LP（https://stand-by.jp/campaign_202612）を作るとしたらどう進めるか、という **工程の再現** で、実際の作業の記録ではありません。
- 医療機関のサイトです。施術名・価格・期間・本文は **公開中の LP に書かれているものだけ** を使い、効果や安全性についての説明は加えていません。
- **本物のもの**
  - ブラウザに出るサイト（トップページ、今回の LP `/campaign_202612`、前回の LP `/campaign_2`、404 ページ。PC 幅 1920px / スマートフォン幅 390px）は、公開中のサイトの画面をそのまま取り込んだものです（`js/site-snapshot.js`・`assets/site/`。2026-11-17 取得）。
  - WordPress の管理画面は **すべて本物の WordPress 7.1 の画面** です（日本語。下の「WordPress の画面について」）。プラグインは公開サイトの REST API に出ているもの（Yoast Duplicate Post・WP Super Cache・All-in-One WP Migration・Site Kit by Google）を wordpress.org から入れ、日本語の翻訳も公式のものです。
  - 固定ページ一覧のタイトル・スラッグ・親ページ・日付・ID、前回の LP（ID 442）の本文とバナー（ID 627）、今回の LP の ID 677 とバナーの ID 678 は、公開サイトの REST API とページから取ったものです。
  - LP の本文（タイトル・対象期間・詳細・施術内容一覧・注意書き）と料金、バナー画像（`2612-2701_…_.png`、982×446）は公開中の LP のものです。料金表の元データ（`data/price-202612.csv`）は LP の「定価⇒キャンペーン価格」から逆に起こしたもので、スクリプトの出力は LP と一致します。
  - トップページのバナーのマークアップ（2 つ目のバナーの `alt` が 1 つ目のコピーのままなのも本番どおり）、新しい固定ボタンの HTML（`<!-- footer_2 -->` の `sticky-footer-wrap`）と 追加 CSS（`docs/lp/sticky-cta.css` と PC で隠すルール）、コメントアウトされた古いボタン（`#bottomWebBtn`）とその画像は、公開サイトの HTML・CSS・テーマのファイルそのものです。
- **再現のもの**
  - VS Code のプロジェクト：テーマのソースは公開されていないため、`front-page.php` `footer.php` などは公開ページの HTML から必要な部分だけを書き起こしたものです（マークアップ・クラス名・アドレスは本番どおり、PHP は最小限）。依頼メモ（`docs/lp/campaign-202612.md`）・料金のスクリプト（`scripts/campaign-price.mjs`）・`scp` での反映先・ターミナルの出力も説明のためのものです。
  - WordPress のテーマ「Stand by Beauty Clinic」（`stand_by_beauty_clinic`）は `style.css` のヘッダーと `screenshot.png` が本物で、PHP は代わりのものです。そのため管理画面の **カスタマイザーのプレビュー枠には公開サイトの画面をはめ込んで** います（下の「WordPress の画面について」）。
  - 作業の前の状態（トップのバナーが 1 つ、スマホ下部の古い画像ボタン、追加 CSS にボタンの CSS がない状態）は、取り込んだ公開ページにその状態を当てはめて再現しています（`js/apps.js` の `oneBanner` `oldCta` `cssBefore` `cssPasted`）。
  - 3 つのミス（下の表）は演出です。ログインのユーザー名は検証用 WordPress の `admin`、パスワードは伏せ字です。
- Stand by Beauty Clinic は実在の医療機関です。このデモはローカルのファイルとしてだけ使ってください（Web に公開しないでください）。

## 録画の手順

1. `public/videos/wp-stand-by-lp/index.html` を **Google Chrome** で開く（ダブルクリックで可。サーバーは不要。`npm run dev` 中なら http://localhost:3000/videos/wp-stand-by-lp/index.html でも可）
   - 準備に 5〜20 秒ほどかかります（サイトの画面・WordPress の画面・画像・フォントの先読み）。タイトル画面が出たら準備完了です
2. **F11** で全画面表示にする（推奨：1920×1080、ブラウザのズーム 100%）
3. 画面録画を開始する
4. **Space** キーで再生開始
5. 最後に「キャンペーン LP が完成」と出たら録画を停止

## 再生される内容

| STEP | 画面 | 内容 | ミスと修正 |
| --- | --- | --- | --- |
| 1 構成・導線設計 | VS Code・Chrome（stand-by.jp） | 依頼メモ（タイトル・期間・割引・特別価格・バナー）を確認 → 公開サイトのトップのバナーから前回の LP（`/campaign_2`）へ、構成（タイトル → バナー → 対象期間 → 詳細 → 施術内容一覧 → ご予約はこちら）を確認 → 導線をメモ（トップにバナー 2 つ、スマホは画面下の固定ボタン） | |
| 2 キャンペーン価格 | VS Code ＋ ターミナル | 定価の CSV（12/1 からの定価・U18 区分・特別価格）から LP の料金表（Markdown）を作るスクリプトを書いて実行 | **計算ミス**：特別価格の列を使わず全部 30％オフにしていたため、糸リフトが ¥10,500（依頼は ¥10,000～）、鼻・ボラックスも違う → `special ? Number(special) : price * 0.7` に直して再実行 |
| 3 LP の作成 | Chrome（WordPress） | ログイン → 固定ページ一覧 → 前回の LP を Duplicate Post の「新規下書き」で複製 → タイトルを入力 → 画像ブロックの「置換」でバナーをアップロード → アイキャッチ画像をメディアライブラリから選択 → 対象期間を入力 → 詳細を依頼メモから貼り付け → 料金表（スクリプトの出力）を貼り付け（`###` は見出しブロックになる）→ 公開 → 「固定ページを表示」 | |
| 4 トップからの導線 | VS Code・Chrome | `front-page.php` のバナーをコピーして 2 つ目を追加（リンク先 `/campaign_202612`、12-1月のバナー）→ `scp` で反映 → WP Super Cache でキャッシュを削除 → トップに 2 つ並んだバナーをクリック | **リンク切れ**：`/campaign_202612` が 404。公開したページのスラッグがタイトルから自動で作られた日本語（`新しい自分で新年を迎える！12-1月限定キャンペー`）のままだった → エディターのスラッグを `campaign_202612` にして保存 → LP が表示される |
| 5 固定ボタン（CTA） | Chrome（スマホ表示）・VS Code・Chrome（カスタマイザー） | スマホ下部の古い画像ボタンを確認 → `footer.php` で古いボタンをコメントアウトし、WEB予約／LINE の 2 つのボタンの HTML を入力 → `scp`・キャッシュ削除 → 外観 › カスタマイズ › 追加 CSS：ボタンの CSS を貼り付け | **表示ミス**：PC のプレビューにも画面下の固定ボタンが出る（PC はヘッダーに予約ボタンがある）→ 画面幅 768px 以上で `.sticky-footer-wrap` を非表示にするルールを入力 → 公開 |
| 6 スマホで確認 | Chrome | スマホ幅の LP：画面下に WEB予約・LINE のボタンが固定され、料金表をスクロールしても残る → トップのバナーはスマホで縦に 2 つ → PC：バナーは横に 2 つ、固定ボタンは出ない → バナーから LP へ | |

### 日本語入力（Microsoft IME と同じ流れ）

依頼メモの導線・スクリプトのコメントと文字列（`、18歳以下` `⇒` `・`）・ボタンの文言（`WEB予約` `24時間受付` `LINEから無料相談・予約`）・LP のタイトルと対象期間・追加 CSS のコメントは、
ローマ字を 1 キーずつ入力 → 変換 → 確定 の流れで入力しています。英数字は IME をオフにして入力し、画面下に押したキーを表示します。

## WordPress の画面について

- 管理画面（ログイン・ダッシュボード・固定ページ一覧・ブロックエディターの各段階・メディアライブラリ・公開パネル・スラッグ・WP Super Cache・カスタマイザーの追加 CSS）は、
  **WordPress Playground（ブラウザの中で動く本物の WordPress）を stand-by.jp と同じ構成にして、実際に操作した画面を取り込んだもの** です（`tools/snapshots/wp-stand-by-lp/capture-wp.js` → `js/wp-snapshot.js`・`assets/wp/`）。
  - サイト名・キャッチフレーズ、WordPress が `/wp` にあること、プラグイン、45 件の固定ページ（タイトル・スラッグ・親・日付・ID）、前回の LP の本文とバナーは公開サイトから取って設定しています。追加 CSS は公開サイトのものから、動画で足す 2 か所（固定ボタンの CSS・PC で隠すルール）を抜いた状態から始めています。
  - 複製は Duplicate Post の「新規下書き」を実際に押したもの、画像の「置換」メニュー・アイキャッチ画像のメディアライブラリ・公開・スラッグの変更・キャッシュの削除・追加 CSS の公開も実際の操作です。複製したページが ID 677、アップロードしたバナーが ID 678 になるように ID を合わせています（公開サイトと同じ）。
  - 自動で作られたスラッグ（タイトルの先頭、URL エンコードで 200 バイトまで）は WordPress が実際に作ったものです。
- 取り込んだ画面に後から手を入れているもの（`js/apps.js`）：
  - Playground の環境だけに出るお知らせ（WP Super Cache の「CRON システムは停止中」「wp-content が書き込み可能」）は取り除いています。
  - カスタマイザーのプレビュー枠には、代わりのテーマの画面の代わりに公開サイトのトップページをはめ込み、追加 CSS の段階（CSS なし → 貼り付け → PC で隠すルール）に合わせて CSS を差し替えています。
  - 追加 CSS のエディター（CodeMirror）のスクロール位置とブロックエディターの本文のフォント（取り込みで失われた既定のゴシック体）は、取り込んだときの画面に合わせて戻しています。公開日時の表示（「今日 1:47 PM」など）は、動画の時計で公開した時刻にしています。
  - 入力欄への入力（ユーザー名・タイトル・対象期間・スラッグ・追加 CSS のルール）は、本物の画面の上で文字を表示しています。
- WordPress の管理画面にはファビコンがないため（サイトにサイトアイコンが設定されていない）、管理画面のタブには Chrome 本体のアイコンを表示しています。サイトのタブはサイトのファビコンです。

## 演出であるもの

- **画面の環境**：VS Code は今の既定の見た目です（Dark Modern テーマ、codicon、Seti のファイルアイコン、ミニマップ）。
- ターミナルの出力（`scp`・スクリプトの結果）は、実際のコマンドの出力の形式に合わせて表示しています。ファイルの選択ダイアログに並ぶほかのファイルは演出です。
- 時刻：13:30 に始まり、作業の切れ目で時計が進みます（LP の作成 13:46、導線 14:02、固定ボタン 14:17）。

## 取り込み直す場合

```
npm run snapshot -- wp-stand-by-lp                                  サイトの画面（js/config.js の snapshot）
node tools/snapshots/wp-stand-by-lp/fetch-assets.js                 古い固定ボタンの画像（公開ページでは読み込まれていないため）
node tools/snapshots/wp-stand-by-lp/capture-wp.js                   WordPress の画面（Playground、5 分ほど）
node tools/webp.js wp-stand-by-lp                                    画像を WebP に
node tools/snapshots/wp-stand-by-lp/capture-wp.js --post             取り込み後の書き換えだけをやり直す
```
