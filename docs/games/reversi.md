# 喫茶しろくろ（reversi）

`public/games/reversi/` ― リバーシ（CPU 対局・ふたりで対局）

## 概要

昭和レトロの純喫茶「しろくろ」で、店の人たちとリバーシを打つゲームです。対局相手は、マスターの孫の「ひなた」（入門）、看板猫の「むぎ」（初級）、昼休みの常連の会社員「律子」（中級）、店主の「マスター」（上級）の 4 人。1 台の画面でふたりで対局することもできます。待った・ヒント・石差つきの結果・相手ごとの成績（勝敗と最大石差）を記録します。盤と石はすべてコードで描いています。

## 遊び方（操作）

- タイトルで「CPU と対局／ふたりで対局」、対局相手、あなたの石（黒＝先手／白＝後手／おまかせ）を選び、「対局開始」。途中でやめても「続きから」で再開できます。
- 石を置けるマスに小さな点が出ます。マスをタップ（クリック）すると石を置き、はさんだ石が置いた場所から順に裏返ります。マウスでは置ける場所に石の影が出ます。
- **待った**：自分の最後の手まで戻します（CPU が考えている途中でも取り消せます。ふたりで対局では 1 手戻します）。**ヒント**：上級の CPU が約 1 秒考えたおすすめのマスを光らせます。**最初から**：確認のうえ、やり直します（終局後は「もう一局」）。
- キーボード：矢印キーでカーソル、Enter / Space で置く、H でヒント、Z（Backspace）で待った。
- PC（横長）では盤の左上に相手、右下に自分とボタン。スマホ（縦長）では上に相手・下に自分・その下にボタン。

## ルール（採用したルール）

- 8 × 8 の盤、中央の 4 マスに白黒 2 つずつ（d4・e5 が白、d5・e4 が黒）を置いて始め、**黒が先手**。
- 相手の石を縦・横・ななめのどれかの方向で自分の石ではさめるマスにだけ置け、はさんだ石（複数の方向ならすべて）を裏返します。
- 置ける場所がないときは**パス**（自動。画面に「パス」と表示）。置ける場所があるときはパスできません。両者とも置けなくなったら**終局**（盤が埋まった場合を含む）。
- 終局時に石の多い方の勝ち。同数は引き分け。**空きマスはどちらにも数えません**（石の数そのままで石差を表示）。
- 名前は「リバーシ」とし、商標である別の名称は使っていません。

## 独自の要素（既存作品との違い）

- 舞台（純喫茶）・キャラクター・セリフはオリジナル。相手は対局の始まり・隅を取った／取られたとき・パス・終局で吹き出しで話します。
- 盤は「緑の盤面」ではなく、真鍮色の線を入れたウォールナットの木の盤（コードで木目を描画）。石は光沢のある白黒の円盤で、裏返るときは縦軸で回転し、置いた場所からの距離に応じて順番に返ります。
- BGM は喫茶店らしいゆったりしたオリジナルの曲（F 長調、ウォーキングベース・裏拍のコード・ハイハット）。石を置く音・裏返る音（返した数だけ音が上がる）も WebAudio で合成しています。

## 画像

画像は 6 枚（キービジュアル・店内の背景・対局相手 4 人）。いまは画像サンプルで、盤・石はコードで描くため、サンプルのままでも遊べます。

- 生成プロンプト：[prompts/reversi.md](prompts/reversi.md)
- ツール：Ideogram（ポスター風のキービジュアル）、Midjourney（店内の背景。キービジュアルを `--sref` にして色調をそろえる）、niji・journey（4 人の顔。1 枚目を `--sref` にして絵柄をそろえる）

## 技術メモ

- ファイル：`rules.js`（盤・合法手・裏返し・perft。ページ・Worker・Node で共通の UMD）、`ai.js`（思考）、`worker.js`（Web Worker）、`game.js`（画面・入力・対局の流れ）、`style.css`、`images.json`。
- 盤は 10 × 10 の配列（外周が壁）で、8 方向を index の差（±1・±9・±10・±11）で調べます。
- CPU（`ai.js`）：
  - 入門：置けるマスから、位置の重み（隅が高く、隅の隣が低い）に応じた確率でランダムに選ぶ。
  - 初級：返せる数 × 3 ＋ 位置の重み（＋小さなゆらぎ）が最大の手（欲張り＋位置）。
  - 中級：4 手先までのアルファベータ探索。評価＝位置の重み（隅を取ったあとの X・C 打ちは減点しない）＋ 着手可能数の差 ＋ 隅 ＋ 辺の確定石 ＋ 開放度（空きマスに接する石）＋ 終盤の石数。
  - 上級：同じ評価で反復深化（6〜10 手先、約 1.6 秒）。**残り 14 マス以下では最後まで読み切り**（相手の着手可能数が少ない手から読む fastest-first、時間の上限 3.5 秒、超えたら通常の探索に切り替え）で、最終的な石差を最大にする手を選びます。
  - Node での対局（入門 vs 初級・初級 vs 中級は先後 6 局ずつ、中級 vs 上級は 2 局ずつ）で、初級 > 入門（12 局中 8 勝 1 分）、中級 > 初級（12 戦全勝）、上級 > 中級（4 戦全勝）を確認しました。
- 思考は Web Worker で行い、画面は固まりません（上級の思考中の描画の最大間隔を 1024×768 などで計測、通常 18〜33 ms）。Worker が使えない環境では、ページの中で短く（最大 0.7 秒）考えます。
- 検証：
  - perft（初期局面からの局面数。パスも 1 手として数える）を Node で確認：深さ 1〜7 = 4、12、56、244、1,396、8,200、55,092（さらに 8 = 390,216、9 = 3,005,288 も一致）。
  - 単体テスト：20 手指して全部戻すと初期局面に戻ること、残り 12・14 マスの完全読み（14 マスで約 0.5 秒）。
  - `npm run game-check -- reversi`：PC・スマホでタイトル → d3 に置く → CPU の応手 → ヒント → 待った → CPU がパスする局面 → 最後の 1 マスで終局 → 結果（64 対 0）→ 盤面を見る → ふたりで対局、まで自動で実行。1024×768・768×1024・844×390・390×844 も別のスクリプトで確認。
