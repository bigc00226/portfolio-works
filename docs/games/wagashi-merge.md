# 和菓子ころりん（wagashi-merge）

重箱に和菓子を落として、同じお菓子どうしをくっつけると、ひとつ大きなお菓子に変わる落ち物パズルです。円の物理演算（転がる・積み重なる・押し合う）を自作し、金平糖から鏡餅まで 11 種類の和菓子を育てます。

- 場所: `public/games/wagashi-merge/`（`index.html`・`physics.js`・`game.js`・`style.css`・`icon.svg`・`images.json`・`img/`）
- 画像のプロンプト: [prompts/wagashi-merge.md](prompts/wagashi-merge.md)

## 概要

- 画面: タイトル → プレイ → 結果。右上の丸ボタンからいつでもメニュー（つづける・最初から・タイトルへ）、遊び方、音の切り替え。
- モード: **じっくり**（時間無制限・はみ出したら終わり）と **三分勝負**（3 分間のスコアアタック、BGM が少し速い）。ベストスコアはモードごとに保存（`GK.store` の `best-free`・`best-timed`）。
- 記録: 作ったことのあるお菓子（`seen`）を保存し、タイトルの「お品書き」の列に表示します。タイトルのメニューから記録を消せます。
- 画面の構成: スマホの縦長は「上に得点・つぎ・ご注文・お茶、中央に重箱、下にお菓子の順番の列」。PC と横長は「中央に重箱、左に得点・つぎ・ご注文・お茶、右にお品書き（11 種類の一覧と点数）」。

## 遊び方（操作）

| 操作 | スマホ | マウス | キーボード |
|---|---|---|---|
| 落とす位置を決める | 画面をなぞる | 動かす | `←` `→`（`A` `D`） |
| 落とす | 指をはなす | クリック | `Space`・`↓`・`Enter` |
| お茶を使う | 「お茶」ボタン → お菓子をタップ | 同じ | `T` → `←` `→` でえらんで `Space`（`Esc` でやめる） |

落とすお菓子は箸でつまんで重箱の上に持っています。点線のガイドと、着地する位置の丸い影が出ます。

## ルール

1. 落ちてくるのは小さい 5 種類（金平糖・黒豆・栗きんとん・桜餅・草餅）。次のお菓子は「つぎ」に表示。
2. 同じお菓子どうしが触れると合わさって、次の段のお菓子になります。順番は
   金平糖 → 黒豆 → 栗きんとん → 桜餅 → 草餅 → 最中 → 水まんじゅう → おはぎ → どら焼き → 大福 → 鏡餅（11 段）。
3. 点数: 段 k のお菓子ができると 5 × k² 点（黒豆 5 点 … 鏡餅 500 点）。1.1 秒以内に続けて合わさると「れんさ」で 1.5 倍・2 倍・2.5 倍…。鏡餅どうしを合わせると、ふたつとも消えて 1,500 点（れんさ倍率つき）。
4. 重箱の赤い点線より上に、落ち着いたお菓子がはみ出したまま 3 秒たつとおしまい（カウントダウンが出ます）。三分勝負は時間切れでも終わります。

## 独自の要素（既存作品との違い）

ジャンル（落として同じものを合わせる物理パズル）は一般的ですが、題材・見た目・段の順番・ルールの追加要素はすべてこのゲームのオリジナルです。果物は使わず、和菓子 11 種の順番と大きさ・配色も独自に決めました。

- **ご注文**: 茶屋に「ご注文」が入り、札に出ているお菓子を作るとボーナス（その段の点数の 2 倍）と **お茶** 1 杯。ご注文は、これまでに作った一番大きなお菓子より少し上の段から選ばれます。
- **お茶（ひと休み）**: ご注文の完成か 3 れんさ（6 れんさ）でもらえ、最大 3 杯（最初に 1 杯）。使うと好きなお菓子をひとつ「いただきます」して取りのぞけます（湯気の演出）。詰まったときの救済であり、どこを空けるかの判断が戦略になります。
- **箸でつまむ演出・重箱**: 落とす前のお菓子は漆塗りの箸でつまんで持ち、器は黒漆に金の線と金具の重箱（中は檜）。お品書き（右のパネル）で段の順番と点数がいつでも見られます。
- 音楽は陽音階（D E G A B）で新しく作った曲。合わさる音も陽音階で、段とれんさが上がるほど高くなり、大きなお菓子では太鼓の低音が入ります。

## 技術メモ

- **物理（`physics.js`、ブラウザでも Node でも動く）**: 小さなステップに分ける位置ベースの解法（Müller ほか "Small Steps in Physics Simulation" / XPBD の剛体の考え方）。1/60 秒を 10 サブステップ（600 Hz）に分け、各サブステップで「積分 → 円どうしの重なりを質量比で押し戻す → 壁と床（無限に高い壁なので外に出ない）→ 位置から速度を求める → 速度の段階で反発（係数 0.16）とクーロン摩擦（回転つき・円板の慣性 ½mr²）、転がり抵抗」。摩擦の上限は押し戻しの量から求めた垂直抗力で決めるので、積み重ねが安定し、静止時の揺れ（ジッター）が出ません。
- **爆発の防止**: 合わさってできたお菓子は 0.16 秒かけて大きくなり、成長中・落とした直後のお菓子の押し戻しは 1 サブステップ 3 単位までに制限。速度の上限 1,500 単位/秒。1 サブステップの移動は最大 2.5 単位で、一番小さい半径（14）より十分小さいので、すり抜けません。
- **固定ステップ**: ゲームの進行は 1/60 秒の固定ステップ（1 フレームに最大 4 回）で、描画とは独立。乱数はシード付き（`GK.rng`）。
- **描画**: 背景と重箱は画面サイズが変わったときだけオフスクリーンの canvas に描き、毎フレームは 1 枚貼るだけ（描画の JS は 1 フレーム 0.5 ms ほど）。
- **検証**:
  - Node で `physics.js` を直接読み込み、6 分間ランダムに落とし続けるテスト: NaN なし、重箱の外に出たものなし、重なりの最大は小さい方の半径の 25%（落下の衝突の瞬間だけ）。50 個積んで 5 秒置くと速度 0・移動 0（ジッターなし）。床を転がる最中は 1.3 秒で止まる。上から 1,500 単位/秒で撃ち込んでもすり抜けない。
  - `window.__gameSelfTest`（`npm run game-check` が実行）: 2 分ぶんのランダムなプレイ（約 210 個落とし、はみ出したら新しいゲーム）で NaN・はみ出し・重なり 35% 超がないこと、桜餅 2 つ → 草餅と点数、お茶で 1 個減ること、はみ出し → 結果画面、三分勝負の時間切れを確認し、プレイ・結果・タイトルを撮影。
  - puppeteer で、スマホのタッチ（なぞって離す）・PC のマウス（動かしてクリック）・キーボード（`→` `Space` `T`）で実際に落とせること、1440×900・390×844・1024×768・768×1024・844×390 でスクロールしないことを確認。
